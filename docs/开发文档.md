# 绒伴：具有情境记忆的 AI 语音桌宠

罗森 · 202405100233

课程选题：C3 本地智能语音助手、P4 分享 / 导出卡片

## 1. 需求分析

绒伴面向希望获得轻量陪伴与日常整理帮助的安卓用户。用户通过悬浮桌宠或主 App 发起语音、文字互动。手机本地完成中文识别、指令解析、记忆保存、专注计时和卡片生成，开放式聊天与内容总结连接用户配置的模型服务。

主 App 的核心流程是进入陪伴页、发起对话、执行本地指令或获得 AI 回复、确认候选记忆、在下一段对话中引用相关记忆。伴生模块的核心流程是从独立桌面入口进入卡片工作室、选择主 App 的记忆或对话、编辑、预览、导出或分享。

主 App 包含陪伴、对话列表、对话详情、记忆列表与详情、技能列表与详情、设置。持久化使用 Room 和 DataStore，设备能力使用麦克风与本地语音推理，异步任务使用协程和 ViewModel。用户拒绝麦克风后可文字输入，拒绝悬浮权限后可在主 App 使用同一功能。

## 2. 产品与界面

界面采用奶油白、鼠尾草绿、杏橙色，角色是原创团子猫“绒绒”，名称可以修改。首页提供语音入口、心情选择、记忆入口、卡片入口和专注进度。角色状态包含待机、倾听、思考、说话、开心与休息。角色以 Android 绘制和 Compose 动画展示，思考提示使用原创 Lottie 动画。

悬浮桌宠由用户主动开启，可拖动和吸附至屏幕两侧。点击打开可见互动界面后才录音。前台通知提供休息和关闭入口。App 不读取其他应用的屏幕内容，情境来自时间、用户选择的心情、对话与专注状态。

## 3. 系统设计

三个 Gradle 模块：app 承载主界面、ViewModel、悬浮服务与专注提醒；core 承载本地数据、配置、凭证、模型协议、语音、记忆与卡片绘制；cards 提供可独立启动的卡片工作室。Hilt 提供数据库与服务实例，页面订阅 Flow，Room 调用在协程内执行。

模型配置使用统一协议字段、Base URL、模型名和独立凭证标识。支持兼容 Chat Completions 的服务、Anthropic Messages 与 Gemini GenerateContent。协议适配器将服务端事件统一为可见文字流，不实现工具循环或自主 Agent。

默认配置为 MiMo Token Plan 中国接口和 mimo-v2.6-pro。凭证以 Android Keystore 的 AES/GCM 密钥加密，仅在当前设备保存。源码、构建产物、日志和导出内容不包含预置凭证。开发者可通过调试安装的私有一次性文件完成本地注入；导入后文件删除。

## 4. 数据库与配置

| 实体 | 主要字段 | 用途 |
| --- | --- | --- |
| Conversation | id、title、created | 对话列表与导航 |
| Message | id、conversationId、role、content、state、created | 对话内容与生成状态 |
| Memory | id、title、content、aliases、kind、source、sourceConversationId、enabled、pending、updated | 可审阅、可停用的长期和情境记忆 |
| Skill | id、name、description、body、executor、enabled、builtin | 内置和提示技能 |
| CardDraft | id、title、body、template、source、created | 独立卡片工作室草稿 |

Preferences 存储桌宠名称、心情、主题、姓名学号、专注结束时间、记忆开关、供应商列表和当前供应商。凭证独立于这些配置加密保存。Room 导出数据库 schema，便于后续版本升级时检查兼容性。

## 5. 关键实现

### 5.1 离线语音

复用 sherpa-onnx 1.13.8 的 Android 动态库及 Kotlin JNI 包装。中文识别使用 Zipformer int8 流式模型，采集 16kHz 单声道 PCM；中文合成使用 AISHELL3 VITS 模型。模型与实际使用的规则随演示安装包提供，不需要首次联网下载。

AudioRecord 读取、模型推理与合成在后台协程执行。先显示模型准备状态，开始录音后显示倾听状态，采集在停顿或 30 秒后结束。识别结果进入可编辑输入框，由用户校正和发送。录音权限不可用时给出替代提示。退出页面时停止录音与播放，在 finally 块释放 AudioRecord、AudioTrack、识别流和模型实例。

### 5.2 自定义指令引擎

CommandParser 将“记住”“记一下”等同义词映射到明确指令，识别阿拉伯数字与中文数字形式的专注时长。没有内容时追问，后续回复补齐参数，新的明确指令可以覆盖追问。专注时长限制为 1 至 180 分钟。常用指令在联网聊天前解析，由预置执行器完成操作。被停用的内置技能不会执行。

专注结束时间持久化，使用系统允许的后台提醒能力，不申请精确闹钟权限。系统节电状态可能延后通知，首页根据保存的结束时间显示真实进度。

### 5.3 情境记忆

明确的“记住”指令直接保存；普通对话中的事实通过模型提取后进入待确认列表。用户可确认、忽略、编辑、删除和停用。完全相同的内容去重。记忆检索组合关键词、别名匹配和时间排序，只引用已确认且启用的记录。

聊天上下文由角色设定、当前时间、用户心情、专注状态、相关记忆、近期摘要、主动选择的提示技能和近期会话组成。对话与记忆有长度预算，避免无限增长。达到指定对话轮次后生成近期摘要。删除记忆时清理近期摘要，减少旧信息再次进入跨会话上下文的机会。原始对话与长期记忆分别管理。

### 5.4 技能管理

复用 RikkaHub 的 YAML frontmatter 解析器和路径校验代码，保留来源和许可证。导入单个 SKILL.md 文件，要求 name、description 和非空正文，限制大小为 64KB。SafeConstructor 不执行 YAML 对象构造。导入技能仅提供提示内容，不执行脚本、终端命令或手机工具。

内置技能为记住一件事、回忆近况、开始专注、今日回顾、生成卡片、鼓励陪伴。提示技能通过用户选择后传入当前会话，模型输出仍作为普通文字处理。

## 6. P4 伴生模块

卡片工作室在同一 APK 中提供第二个桌面入口“绒伴卡片”，通过共享 Room 数据库读取主 App 的记忆、对话与草稿，不要求先打开陪伴首页。

模板包含对话摘录、记忆便签和今日回顾。使用 Android Bitmap、Canvas 和 StaticLayout 绘制 1080 × 1440 图片。按实际行高分页，正文不会因超长被静默截断。单页保存 PNG，多页保存包含 PNG 的 ZIP；分享时使用 ACTION_SEND 或 ACTION_SEND_MULTIPLE、FileProvider 与临时 URI 读权限。保存位置由系统文件选择器决定，不申请广泛存储权限。

记忆页提供按用户勾选记录导出 CSV，包含 UTF-8 BOM、引号和换行转义，并对公式起始字符作文本处理。

## 7. 测试与问题记录

核心 JVM 测试覆盖中文时长、空参数、记忆筛选、相关性排序、CSV 转义、技能格式、三种模型协议的可见文字与流式失败。已完成一次真实 MiMo 请求，返回 HTTP 200 与指定模型回复。

设备测试分别验证中文 TTS 产生有效音频，以及未修改的上游人声样本通过 ASR 得到预期关键句；同时验证数据库关闭重开后的持久化、长文分页完整性、PNG 输出和记忆界面主流程。真实 MiMo 界面测试验证跨会话记忆、流式聊天和独立卡片分享。最终结果与界面证据另见测试报告。

开发期间修复了记忆排序的类型推断问题、测试模块缺失的 Room 依赖、过时的 SDK CI 安装步骤，并移除了未使用的巨大语音规则文件。识别热词文件曾因混用绝对路径和 AssetManager 导致原生进程退出，已改为统一的资源相对路径，并增加初始化回归测试。合成音频与识别模型的闭环出现误字，因此不把它当作人声识别准确率证据。模拟器自身启动与 gRPC 崩溃问题单独记录。

## 9. 开源与总结

RikkaHub 提供技能解析代码及记忆、模型协议设计参考；Now in Android 提供分层、生命周期和 Flow 实践；sherpa-onnx 提供语音模型运行时。网络、数据库、配置和依赖注入使用成熟库。项目保留 AGPL-3.0 及其他适用许可证，具体来源见 THIRD_PARTY.md。

绒伴将本地设备能力、可管理的记忆和独立分享模块组合成可解释的课程项目。首版重点是把用户可见的核心流程做完整，后续可在真实设备上继续优化语音速度、角色动作和长期记忆质量。
